# Linux packaging

| File | Used by |
|------|---------|
| `tokenburn-gui.desktop` | `.deb`/`.rpm`, AppImage, AUR — `StartupWMClass` and the window's Wayland `app_id` / X11 `WM_CLASS` are all `tokenburn-gui` |
| `tokenburn-tui.desktop` | same; `Terminal=true` so launchers open it in a terminal |
| `tokenburn-gui.metainfo.xml` | AppStream metadata for software centres |
| (icons) | `assets/icons/` — generated by `python3 scripts/gen_icons.py` |

Build everything locally: `just package-linux 0.1.0` (`.deb` + `.rpm`, needs `dpkg-deb` and `alien`),
`just package-appimage 0.1.0` (needs `appimagetool`), `just build-musl` (static CLI/TUI/web, needs `musl-tools`).

**Why one GUI binary covers X11 and Wayland on every distro:** it links only libc and libm. winit
and wgpu `dlopen` X11, Wayland, xkbcommon, EGL and Vulkan at runtime, choosing Wayland when
`WAYLAND_DISPLAY` is set and X11 otherwise, and iced falls back from the GPU renderer to software
rendering. That is why the packages only hard-depend on `libxkbcommon0` and merely *recommend* the
display-server libraries.
